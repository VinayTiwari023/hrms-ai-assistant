# Server-Sent Events (SSE) Streaming Protocol — Phase 6

## 1. Overview

The HRMS AI Assistant provides a real-time token streaming endpoint:

```http
POST /api/v1/chat/stream
Content-Type: application/json
Accept: text/event-stream
Authorization: Bearer <access_token>
```

Responses are streamed using the W3C Server-Sent Events (SSE) protocol. Each frame contains an `event:` line, a `data:` payload line with JSON, and a double newline delimiter (`\n\n`).

---

## 2. Event Protocol Specification

| Event Name | Timing | Payload Structure | Description |
|:---|:---|:---|:---|
| `message_start` | Immediately on request validation | `{"conversation_id": str, "created_at": str}` | Signals stream initialization and links the session. |
| `tool_call_start` | Before executing a tool | `{"tool_name": str, "call_id": str}` | Emits sanitized tool identifier. Private arguments are never streamed. |
| `tool_call_result` | After tool completes | `{"tool_name": str, "call_id": str, "success": bool, "execution_time_ms": float}` | Diagnostic execution timing and success flag. |
| `citation` | When RAG retrieves sources | `{"title": str, "source": str, "section": str \| null}` | Emitted for each grounded knowledge excerpt used. |
| `content_delta` | During token generation | `{"delta": str}` | Incremental content tokens generated by the LLM. |
| `message_complete` | At successful turn completion | `{"conversation_id": str, "message_id": int, "content": str, "citations": list, "tool_calls_summary": list, "response_status": str, "created_at": str}` | Final complete message record. Emitted ONLY if turn succeeds. |
| `error` | On failure or interruption | `{"code": str, "message": str}` | Standardized error payload. Terminal event. |

## 3. Streaming Orchestration Flow

```
Client (POST /api/v1/chat/stream)
     │
     ▼
Authenticate JWT Principal
     │
     ▼
Verify / Create Conversation (SQLite)
     │
     ├── Greeting Fast-Path?
     │        ├── (YES) ──► emit message_start ──► emit content_delta ──► emit message_complete (0ms Ollama)
     │
     └── Substantive Message
              │
              ▼
         emit message_start
              │
              ▼
         Model Tool Inspection (Ollama /api/chat)
              │
              ├── Emits Tool Call?
              │        │
              │        ▼
              │   emit tool_call_start
              │        │
              │   Execute Tool (HRMSToolService, Principal Identity Bound)
              │        │
              │   emit tool_call_result
              │        │
              │   [If RAG] emit citation for each chunk
              │        │
              │   Feed result to context and iterate (up to chat_max_rounds)
              │
              ▼
         Stream Final Answer (Ollama /api/chat stream=True)
              │
              ├── [Loop tokens] ──► emit content_delta (check client disconnect)
              │
              ▼
         Persist Completed Turn to SQLite (No duplicates)
              │
              ▼
         emit message_complete
```

---

## 4. Client Disconnect & Timeout Handling

1. **Client Disconnect**: Between each generated token delta, the orchestrator checks `request.is_disconnected()`. If the user cancels the HTTP connection or navigates away, generation terminates immediately and background GPU processing halts.
2. **Atomic Persistence**: An assistant turn is persisted to the database **only** after generation succeeds completely. Interrupted or disconnected turns are never partially committed.
3. **Timeouts**: If Ollama inference exceeds `CHAT_STREAMING_TIMEOUT_SECONDS` (default: 120s), an `error` event with code `LLM_TIMEOUT` is emitted.

## 5. PowerShell Client Example

```powershell
# 1. Login to get JWT Bearer token
$login = Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/auth/login -Method POST -Body '{"email":"alice@novatech.com","password":"securePassword123"}' -ContentType application/json
$token = $login.access_token

# 2. Invoke streaming endpoint using HttpClient
$handler = [System.Net.Http.HttpClientHandler]::new()
$client = [System.Net.Http.HttpClient]::new($handler)
$client.DefaultRequestHeaders.Authorization = [System.Net.Http.Headers.AuthenticationHeaderValue]::new("Bearer", $token)

$requestBody = '{"message":"What is my leave balance?"}'
$content = [System.Net.Http.StringContent]::new($requestBody, [System.Text.Encoding]::UTF8, "application/json")

$request = [System.Net.Http.HttpRequestMessage]::new([System.Net.Http.HttpMethod]::Post, "http://127.0.0.1:8000/api/v1/chat/stream")
$request.Content = $content

$response = $client.SendAsync($request, [System.Net.Http.HttpCompletionOption]::ResponseHeadersRead).Result
$stream = $response.Content.ReadAsStreamAsync().Result
$reader = [System.IO.StreamReader]::new($stream)

while (-not $reader.EndOfStream) {
    $line = $reader.ReadLine()
    if ($line.StartsWith("data: ")) {
        $json = $line.Substring(6)
        Write-Host $json
    }
}
$reader.Close()
$client.Dispose()
```
